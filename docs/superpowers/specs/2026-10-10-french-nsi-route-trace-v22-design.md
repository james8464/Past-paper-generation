# French NSI route-trace V22 — versioned design

Status: implementation design within the approved written-paper scope, 10 October 2026. This is not teacher, examiner, learner, rights or accessibility approval.

## Purpose and boundary

The pinned V21 French subject passed automated checks but remains a manual fidelity hold. Its graph exercise puts ten questions on one dense page after the opening material, while the official 2026 Métropole exercise sustains a linked problem over several pages. This increment makes candidates show intermediate route-finding work before and after a link outage. It must add reasoning and usable working surfaces, not blank pages to chase the official page count.

V22 changes Exercise 1 only. V21's eight-incident database audit, V18's network/process/security exercise, UK routes, and V13–V21 package and checkpoint replay retain their identities. The paper remains three independent Terminale NSI written exercises, 210 estimated minutes, exactly 18 technical points plus a separate two-point indicative French-language component. The practical component is unsupported.

## App-owned case and staged candidate materials

The new immutable V5 graph/tree contract derives from the existing seeded six-vertex weighted graph and five-node binary search tree. Unlike V4, it closes the **first edge of the baseline minimum route from A**. The graph retains another edge incident to A, so the post-closure route remains reachable and the first fixation state necessarily changes. The application, not the model, computes two Dijkstra fixation states before closure and two after closure, using the documented alphabetical tie-break. Each state records the fixed vertex, provisional distances and known predecessors. The post-closure states are recomputed on the surviving edge set and must differ from the baseline states. Both states and final routes are deterministically cross-checked by independent shortest-path calculations. No model-authored code or route facts are executed.

The candidate receives the graph before 1a, then a blank two-row baseline Dijkstra table immediately before 1c. The fixed faulty breadth-first-search code appears with 1e, before any question that depends on its correction. The link closure is introduced at 1g with a second blank two-row Dijkstra table whose heading identifies the closed link. The tables have columns for fixed vertex, provisional distances for A–F and known predecessors, with empty answer cells and clear instructions that ∞ denotes an unreached vertex. The BST material appears before the first tree question, 1h. Each table is associated only with its dependent prompt and cannot appear after that prompt or in an unrelated question. The correction supplies the derived rows and credits; the subject never exposes them.

## Ten connected tasks and exact credit

The sequence remains 1a–1j. Questions 1a–1b establish graph reading and route cost. Question 1c fills the baseline two-fixation table; 1d reconstructs and justifies the baseline minimum route. Question 1e identifies and repairs the fixed breadth-first-search code's undefined variable; 1f traces the corrected program, including its queue state. This reverses the V20 1e/1f dependency, which asked for a corrected trace before the repair. Question 1g fills the post-closure two-fixation table, reconstructs the new minimum route, calculates its cost and compares it with the baseline. Questions 1h–1j apply the independent tree material and debug fixed search code. Native French prompts name every requested element; rubrics cannot credit an unstated result.

The 70-minute E1 estimate and seeded E1 totals of 5.5, 6 or 6.5 technical points remain. Exact quarter-point profiles are inherited from V20. The 1e credit now tests the named exception and corrected variable at the half-point profile, with the undefined-name explanation and corrected line at the one-point profile; 1f's half point tests the corrected traversal order and queue state. Question 1g's four quarter-point criteria credit (1) correct post-closure fixation rows, (2) predecessor evidence, (3) the new route and cost, and (4) the comparison with the original cost. If two fixation rows plus the final route are not realistically achievable in seven minutes, teacher and learner calibration must change the task or estimate before qualification; automated checks cannot settle that. Do not silently redistribute points across other exercises or the language component.

## Version and publication gates

V22 has a separate V5 contract digest, finite French prose catalogue digest, selection schema, prompt identity and explicit provider/pipeline/runtime/PDF/benchmark dispatch. The model selects only registered wording IDs; it cannot change graph edges, closed link, tables, answers, code, marks or source references. Missing or mixed V22/V21 identity fails closed. V13–V21 and UK package/state replay remain unchanged. French reference retrieval remains strictly scoped to eligible French sources, with provenance and holdout isolation and no UK fallback. Local privacy and the non-official subject/proposed-correction labels remain unchanged.

Normal and large-print tests must reject missing, filled, swapped or misplaced baseline/post-closure working tables; mismatched closure labels, question IDs, graph edges, code, answers or quarter-point credits; and subject answer leakage. They must check material-to-question association, readable bounds and correction answer/credit grouping. Render fixture PDFs, visually inspect every page against all official 2026 Métropole pages with the PDF skill, then seek a fresh read-only review and protected Backend/macOS PR checks. After engineering merge run exactly one source/model/reference-pinned French live diagnostic, preserve every attempt and artifact hash, inspect every generated page, and record an honest manual HOLD/PASS. No final UK/French matrix while shared French source changes or manual fidelity holds. Independent NSI teachers, supervised learners, rights review and accessibility evaluation remain external gates.
