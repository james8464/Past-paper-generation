## Candidate-facing case

An eight-incident service register has `agent`, `categorie` and `incident` tables. A faulty report joins `incident.id_agent` to `categorie.id_cat`; two reported category labels happen to match while six do not. The candidate first checks primary/foreign keys and a separately hypothetical invalid insert. They then compute a complete eight-row report comparison, identify the wrong rows and repair the SQL join. Using the corrected relation, they derive category counts, including the behaviour of a separately hypothetical empty fifth category. A short Python function is meant to count closed incidents in category 2, but its predicate compares `id_agent` with 2 instead of `id_cat` with 2. The candidate traces faulty and corrected counts on S0, S1 (close incident 101) and S2 (then close 104). The counts diverge on S0/S1 yet coincide on S2; the candidate explains why that final agreement does not validate the faulty algorithm. Later answers depend on earlier evidence, but each stage restates the input it needs so a single mistake does not make the rest inaccessible.

The V4 incident rows are fixed before seeded names: `(id_incident, id_agent, id_cat, statut)` = `(101,1,2,ouvert)`, `(102,1,3,clos)`, `(103,2,1,clos)`, `(104,3,2,ouvert)`, `(105,2,3,clos)`, `(106,3,1,ouvert)`, `(107,4,4,clos)`, `(108,4,4,ouvert)`. The two updates close 101 then 104. Thus corrected category-2 closed counts are `0,1,2` while the faulty function returns `2,2,2`; category counts at S0 are `2,2,2,2`. These exact values are both a contract oracle and a guard against a plausible but false correction that happens to agree only at S2.

Twelve questions `2a`–`2l` are staged as integrity, report reconstruction, query/aggregate, and algorithm/state verification. The subject supplies the original rows, faulty SQL, a comparison-work table with eight blank rows, a query-result/count work table, the faulty Python function, and a state/trace table. Working surfaces sit beside their dependent questions in normal and large print; no pre-filled answer or rubric leaks into the subject. The correction keeps each answer with its technical-credit criteria. Avoid an orphaned instruction or a page containing only the tail of one table.
