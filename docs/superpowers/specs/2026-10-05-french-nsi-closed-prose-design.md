# Closed factual language for the French NSI graph/tree slice

Status: design amendment for review, 5 October 2026. This supersedes only the
unrestricted-prose authoring boundary in
`2026-10-05-french-nsi-verifiable-exercises.md`; it does not qualify a paper.

## Decision and trade-off

The first graph/tree slice will use a controlled French-language renderer. The
model chooses from versioned, application-owned scenario frames, question
forms and rubric forms; the application inserts only facts derived from the
immutable graph/tree contract. No arbitrary model-authored factual sentence is
printed. Unknown choices and free-text additions fail closed and remain in the
attempt record. This narrows stylistic freedom, but preserves combinatorial
variation through the seed, scene slots and wording choices. Originality must
still be measured against eligible sources and prior generations; the design
must not be advertised as unlimited original question authoring.

The rejected alternatives are further synonym/regex checks (they cannot
verify arbitrary prose) and an unrestricted model draft with a second model's
approval (agreement is not proof). The latter could only be a teacher-reviewed
draft, not an automatically verifiable product.

## Model-to-application boundary

For each A/B/C two-question part, the model returns only documented choice
IDs and the exact locked identifiers/results requested by the part protocol.
Part A also selects a scene frame and approved slot values from a bounded
French lexicon. A choice ID identifies a renderer template, not a pre-rendered
model sentence. No field capable of reaching the final subject or correction
accepts unbounded model prose, including title, context, prompt, answer,
verification and marking criteria. The raw response is preserved with its hash.

The renderer builds the subject in this order: short data-neutral scene, task
instructions with contract-owned values, the graph/tree materials and printed
API/debugging code. Question forms are imperative or interrogative and cannot
add premises. The application owns all vertex labels, edges, weights, routes,
tree keys, algorithm traces, code and task assumptions. Each task has multiple
approved French phrasings; model selection varies presentation but never
changes the operation. No unsupported distractor or explanation is inserted.

Answers and rubric clauses are generated by the same contract-specific
functions, with exact decimal credit summing to each locked question total.
For the current six tasks, the rubric separates independently checkable steps
where credit allows: neighbours versus incident-weight sum, fault versus
corrected behavior, insertion path versus placement, and inorder result versus
stated BST principle. The model may select an approved wording variant but
cannot assign credit or author a factual criterion. These are indicative
rubrics, not examiner approval.

## Fail-closed and evidence rules

The binding rejects unknown IDs, unsupported slot combinations, extra keys,
changed structured claims, changed answer/credit, and any transport text not
explicitly defined as non-rendered diagnostic evidence. It never silently
rewrites a model sentence into an accepted one. Rejected raw responses,
errors, prompt hashes and run identity remain in the part checkpoint. A retry
is a new recorded attempt; it cannot erase a failure.

Use a new authoring/prompt version and an explicit `prose_contract_version` in
the contract binding, checkpoint, manifest and package evidence. An old v10 or
v11 package stays readable under its original rules; it is not upgraded or
relabeled. Resume and package replay re-render every selected form against the
same contract and compare exact hashes. A changed template library invalidates
new checkpoints rather than silently changing a paper.

Every released PDF is extracted before publication and checked against the
contract and rendered text: all graph edge endpoints/weights, tree cells,
printed code/API, question instructions, canonical answers in the correction
only, and exact rubric credit. Visual review of every page against relevant
official references remains separate. If text extraction cannot establish a
fact, publication stops; it is not treated as a passed automated check.

## Qualification and compatibility

TDD first reproduces the independent review's false A–F adjacency claims in
title, context, prompt and marking. Further adversarial cases include a false
generic graph property, an invented tree key, an unknown choice ID, a rubric
credit change, a tampered template version and a changed failed-attempt hash.
Positive fixtures cover multiple scene/wording combinations and every seed
used for the later diagnostic. All previous UK routes and French v10/v11
replays remain unchanged.

The first source-pinned live diagnostic starts only after this source freezes,
full local tests pass, independent review accepts the new boundary, and the
protected PR checks pass. The final shared-source matrix remains later.
Automated success is still an unreviewed draft. Independent French NSI teacher
review, learner calibration, accessibility assessment and personal prize
application details remain external gates. The written component alone is in
scope; no regional partnership or practical-exam support is implied.
