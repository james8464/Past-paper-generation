# Economics numeric-source binding

An owned public `solve_economics_contract` call accepted a changed candidate-visible chart axis while returning the unchanged canonical answer. The source fingerprint, prompt and numerical data still matched the declared source. The same equality gap covered the projected kind, source identifier, source fingerprint and provenance. This was a public input-admission counterexample, not evidence that a default paper or live model produced a mislabelled chart. The normal projection and renderer already take their labels from the same typed source.

The repair admits explicit `edexcel-instance-v2` sources and requires their six projected descriptors to match. The central factory stamps v2 only when constructing new source instances. `EconomicsSource` still defaults to v1, the separate credit-contract version remains v1, and loading an explicit old v1 source does not upgrade it. A v1 projection may still omit historically optional descriptors, but any descriptor it supplies must match its source. The initial typed-source implementation already projected axes and identifiers; its candidate projection did not yet include provenance. No claim is made that every historical API packet contained every current field.

The change also needs a separate recovery namespace. An owned public checkpoint reproduction showed why: a blueprint-only version change at the same path updates the existing checkpoint identity in place and retains its accepted payloads for revalidation. That established behavior is not changed. Instead, the bridge adds the current Economics source-binding version to its Economics-only request identity. A shared, idempotent filename-prefix helper routes the bridge and explicit direct-package paths to the new namespace. Both console entry points still default to no checkpoint. A marked bridge path reaches the plugin unchanged, so its lease, store routing, ownership receipt and retirement agree. The prefix is routing, not evidence that a payload is trusted; normal payload revalidation remains mandatory.

The first axis controls produced six genuine failures and six passing canonical/legacy controls. The later versioned baseline produced 29 failures and 18 passing controls. Its valid v2 control failed because the old model did not admit v2; present-v1 descriptor mutations separately demonstrated incorrect acceptance. Twelve v2 changed/missing cases also failed at unsupported-version admission, so those baseline results are not counted as evidence that the old verifier checked their descriptors. After the repair, valid v2 sources solve and every changed or missing v2 descriptor is refused.

The final focused run passed 173 tests in 2.39 seconds, including 69 new controls, the existing shared checkpoint and ownership tests, Edexcel checkpoint admission, literal numeric answers and changed-source refusals. Five existing PyMuPDF SWIG deprecation warnings remain. The primary testing runtime was used with assertions that the Economics module and real projection functions came from the isolated worktree. Ruff checks, formatting and the diff check passed. Root independently reran all 69 new controls successfully and read the four production deltas and both complete new test files; a separate reviewer also cleared the scoped change.

Compatibility controls check that valid v2 and v1 answers agree, v1 default and explicit serialization/fingerprints remain unchanged, and absent-axis or provenance-absent v1 packets replay. A retained-style v1 Paper 2 blueprint is serialized, reloaded and validated without rebinding; its numeric items solve and its saved assessment package validates without changing bytes. Checkpoint tests retain the original file hash, use a separate empty v2 store, and replay the old identity explicitly. All six other advertised backend subjects retain their exact previous paths across two providers/models and three paper identifiers. Direct implementation and facade controls cover success, failure and cancellation, marked and unmarked paths, and filenames without extensions.
