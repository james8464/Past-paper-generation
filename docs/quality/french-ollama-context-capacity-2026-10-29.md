# French Ollama context capacity policy, 29 October 2026

Requests with trusted operation `french_nsi_authoring` now ask Ollama not to truncate input or shift away earlier context. The local server reports version 0.40.5; its [tagged ChatRequest definition](https://raw.githubusercontent.com/ollama/ollama/v0.40.5/api/types.go) exposes both controls. This is not a blanket compatibility claim for every older or third-party server.

The context remains 16,384. After a response, the provider requires a positive integer input count and nonnegative integer output count. It refuses a candidate if input plus its requested output allowance exceeds the context, if actual input plus output exceeds it, or if output exceeds the requested limit. Missing, boolean or invalid counts also refuse acceptance. [Ollama documents](https://docs.ollama.com/api/usage) input/output usage counts separately from cached input counts. The provider logs actual counts in a normal progress event, with no candidate answers in that event.

Capacity failures carry `context_capacity` diagnostic evidence, not an assertion that the question or model answer is wrong. Recognized native HTTP 400/413 context-length refusals receive the same classification. Other server errors remain errors. No private answer, schema clause or source excerpt is trimmed to make a request fit. These guards rely on the server's controls and metrics; a successful individual run does not qualify arbitrary future inputs.

Each French typed request has one structured-output attempt and one HTTP attempt, with a 600-second socket limit. The pipeline owns its separate, recorded structural regeneration. There is no hidden provider JSON repair multiplying those attempts. The capability harness forwards this scoped timeout for future probes; earlier pinned 180-second results remain unchanged. Other operations retain their existing retries, 180-second socket limit and request fields.

Mocked regressions cover supported request controls, counts, reservation overflow, actual overflow, missing metrics, native context refusal, rejection without hidden retry, strict JSON rather than salvage, unchanged legacy requests and timeout forwarding. No inference was run for this change, and it makes no speed or full-paper quality claim. A one-token preflight was not added: it would be an additional model operation, and its count alone would not prove that the server retained an oversized original prompt.
