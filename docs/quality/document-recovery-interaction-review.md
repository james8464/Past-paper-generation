# Owned PDF recovery interaction check

This opt-in test exercises `DocumentActionController.choosePDFForAccess` and its real Open panel with an isolated `PDFDocumentAccess`. It does not instantiate the full Documents screen: that view owns its default access service, whose bookmark storage is not redirected by SwiftUI's `defaultAppStorage`.

The owned workflow starts with a missing path. The operator cancels the picker, chooses another owned PDF and dismisses the refusal, then restores the original fixture bytes and chooses that exact original path. The test checks the reopened document bytes, its single stored bookmark, unchanged wrong-file and sentinel bytes, and unchanged persistent preferences. UUID defaults and temporary files are removed after controller cleanup. The fixture constructs no application coordinator and invokes no generation, model, network or notification work. The XCTest host can still own its usual app coordinator, so the operator must not use app menus or app-global shortcuts; Go to Folder inside the real Open panel is permitted. No personal document or production source is changed.

The initial operator run completed all three real picker actions and passed the recovery, byte and bookmark checks. The XCTest still failed its full preference comparison: the Open panel changed only `NSOSPLastRootDirectory`, its remembered folder; the other 39 keys matched. That failed run is retained and is not counted as acceptance.

The revised fixture captures the typed original value of that one OS preference. Before deleting its temporary folder, it restores only that key, only when the new bookmark resolves without UI or mounting to the fixture's exact owned folder and all other preference keys still match. An unrelated value, failed resolution or other preference change fails without restoration. The full original preference comparison still runs afterward; no key is excluded and no domain is replaced. This cleanup is specific to the owned picker test, not a production repair. The earlier run's truncated diagnostic description is not used as a substitute for its original bookmark bytes.

The revised fixture, source SHA-256 `59a9ad5fdca5a6e8a29257ea25c853f93fbee6809da9d0051cfceec414fab3c0`, passed its operator run: one test, zero failures, in 228.351 seconds. The operator used all three actual Open-panel interactions: Cancel, another owned PDF followed by its refusal and OK, and the exact restored PDF followed by its one-page preview and Finish. The complete 40-key host preference comparison passed. Root's private typed before/after copies of the single picker-folder value also matched byte-for-byte, and all 81 regular app-data JSON hashes were unchanged. The test host exited after Finish; process absence was independently checked, without relaunch or forced termination.

That result proves cleanup against the revised run's captured baseline. It does not restore or establish equality with the original pre-trial picker-folder value: the first failed run retained only a truncated diagnostic description of that original bookmark. The initial 118.589-second preference failure remains failed evidence, separately retained from the successful rerun. Logs are `tmp/nov6-document-recovery-interactive.log` and `tmp/nov6-document-recovery-cleanup-interactive.log` in the isolated worktree.

The fixture is disabled unless `KELDIN_INTERACTIVE_PDF_RECOVERY_CHECK=1`. This check covers the production controller's real picker path using isolated bookmark storage and owned files. It does not establish sandbox permission enforcement, full Documents-view or interaction coverage, or paper quality.
