# App-owned helper shutdown

[Apple's App Review guideline 2.4.5(iii)](https://developer.apple.com/app-store/review/guidelines/) disallows spawned processes continuing without consent after the user quits a Mac App Store app. The previous native bridge launched streaming generation and short collected requests without central app-lifetime ownership. Generation cancellation alone did not cover every helper request.

`BackendProcessLifecycle` now owns only the exact Process objects launched through BackendClient. A Mutex protects registration, launch and the closing gate as one synchronous transaction. Both run and collect use it, failed launches release their registration, and normal process completion unregisters before the UI finish callback. A premature cleanup callback cannot forget a running helper. Shutdown blocks new launches, requests SIGTERM, waits at most two seconds, then uses SIGKILL only for still-running registered helper objects and waits at most one further second. No process-name search, process-group signalling, Ollama-daemon shutdown or other-app termination is used.

Keldin's existing SwiftUI App lifetime gains a small NSApplicationDelegateAdaptor. With no owned work it permits immediate Quit while closing the launch gate. With helpers it follows Apple's [applicationShouldTerminate](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldterminate(_:)) and [reply(toApplicationShouldTerminate:)](https://developer.apple.com/documentation/appkit/nsapplication/reply(toapplicationshouldterminate:)) contract: terminateLater, asynchronous bounded shutdown, then a termination reply. Failure cancels Quit and reopens launches after that reply while retaining ownership of any stubborn helper. No security entitlement or signing setting changes.

Regression coverage uses injected fake processes for graceful exit, timeout escalation, normal and failed-launch cleanup, late-launch refusal, an in-flight spawn/Quit race, and reopening after cancelled Quit. Separate disposable helper fixtures exercise actual BackendClient streaming and collection paths, normal exit and shutdown. Tests do not load models, access user history or launch the installed app.

The isolated SwiftPM harness compiles the actual lifecycle, BackendClient and app-model source with Swift 5, strict-complete concurrency and warnings as errors. Only unrelated migration and display-copy dependencies are substituted there. This is targeted runtime evidence, not the complete Xcode app acceptance gate. The integrated full native suite, AppDelegateAdaptor build and installed Quit interaction remain release verification steps. No Store approval or complete interaction-coverage claim follows from this change.
