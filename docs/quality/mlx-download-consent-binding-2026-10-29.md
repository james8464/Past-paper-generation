# Bind MLX setup to approved model data

Download-size metadata identifies one immutable repository revision. The former setup path accepted only a model ID, then resolved the current remote default branch. A complete cached-model confirmation could therefore still fetch a newer revision, and a remote size estimate could describe different bytes from those subsequently downloaded.

The setup command now accepts `--revision` and `--local-only`. A revision must be a lowercase hexadecimal commit ID of 40 to 64 characters, not a branch name or path. Remote setup resolves that exact approved revision. Cached setup uses only local files and fails with a recheck request if they are missing or cannot load; it never silently enables network access. Existing unbound CLI calls retain their earlier arguments and runtime-install restrictions. Model loading still uses `trust_remote_code=false` and local-only tokenizer access.

[Hugging Face's download API](https://huggingface.co/docs/huggingface_hub/en/package_reference/file_download) documents commit revisions and local-only resolution. Inspection of the installed library confirms that downloading a full commit hash does not update `refs/main`. Merely pinning setup would consequently leave later generation either resolving stale default-branch data or unable to find a new snapshot.

After successful pinned model loading, Keldin atomically writes a small private approval record under `HF_HOME/keldin-model-approvals`. The hashed filename contains no supplied path. The record permits only schema version, exact model ID and validated revision. Subsequent local model resolution consults that pin and requests the same revision offline. It does not alter Hugging Face branch references. Missing approved data or invalid records refuse rather than falling back to default-branch data. Record reads are capped at 1,024 bytes; unexpected fields, mismatched models, invalid revisions and linked records are rejected. Failed loading creates no approval. Failed replacement preserves the previous record and cleans only its own temporary file.

No actual model or network transport runs in the regression tests. Tests cover exact remote revision, cached local-only policy, future-generation resolution, missing caches, malformed revision/ID input, strict records, failed model loading, atomic replacement failure, explicit local folders and optional CLI arguments. Existing setup, frozen-runtime and no-remote-code tests remain applicable. Native consent must pass its validated approved metadata into these flags before clearing its pending state; backend-only support is not a complete UI acceptance claim.

This change binds consent to model data and preserves functional pinned resolution. It does not establish model answer quality, store approval or full-provider qualification.
